# ModernBabyType — проект на Godot 4

Вся игра лежит в папке `game/`. Открыть её в Godot 4.3+ и нажать F5. Сборка
дистрибутива описана в `README.md` в корне, здесь — устройство кода.

## Управление

Печатать нужно активные (чёрные) буквы, Backspace чинит ошибку, Enter — дальше
после победы или поражения. **F2** — меню игроков (открыть и закрыть, вернуться
тем же игроком), **F11** и **Alt+Enter** — полный экран (**Esc** в полном
экране — обратно в окно, иначе выход из игры), **F3** — отладочная строка.
Внизу экрана подсказка: какую клавишу жать следующей.

Аргументы запуска (после `--`, чтобы Godot их не съел):

- `--all-keys` — весь алфавит активен независимо от прогресса.
- `--no-all-keys` — наоборот, только буквы по прогрессу. Полезно, чтобы
  проверять релизное поведение из debug-сборки.

## Что внутри

- `scripts/main.gd` — игровой экран: герои-спрайты (зайчик и ёж,
  `assets/*.png`), бег по строке, жевание и отрыгивание ртом с наклоном,
  тряска от опечаток и дрожь при близком еже, бросок ежа при поимке.
  Здесь же HUD, уровни, разбивка текста на строки и ввод.
- `scripts/menu.gd` — меню игроков. Отдельная сцена `scenes/menu.tscn`,
  рисуется через `_draw`, шрифт — `SystemFont`. Возвращает выбранного игрока
  сигналом `chosen`.
- `scripts/balance.gd` — сложность в символах/сек (не зависит от ширины
  окна): цель `target_cps` от уровня и EMA темпа игрока, резиновая лента в
  `_process`, pity ×0.75 при поражении, ступенчатая подстройка по итогам.
  Чистая логика без узлов сцены — её удобно тестировать и она не тянет за собой
  сцену.
- `scripts/save.gd` — профили в `user://modern_baby_type.cfg`. Секция `[last]`
  хранит последнего игрока (пустая строка — гость), секция `[profiles]` — по
  имени всё остальное: сложность, серия побед, EMA темпа и точности, скорость
  ежа, флаг «все клавиши», счётчики игр, время последней игры. Сортировка в
  меню — по времени последней игры, при равенстве по имени.
- Моноширинный шрифт (`DejaVu Sans Mono` / `Consolas` / `monospace`) —
  позиции героя и букв считаются от одной метрики `char_w`.
- Текст лежит слоем ниже героев (`z_index = -10`), герои всегда поверх букв.
- Ошибка рисуется ВМЕСТО буквы в клетке, без вставки символа.

### Погони

Ёж идёт строго по следу героя: выходит, когда герой уходит на вторую строку
(появляется строкой выше), дальше только вперёд по строкам без прыжков. Догнать
может лишь сзади на одной строке. Пока герой на первой строке — ёж ждёт,
это разминка без давления.

## Иконки

`icon.png` (512), `icon.ico` и `icon.icns` генерируются скриптом
`../tools/icons/make_icons.py` (нужен pillow из `.venv`), он детерминированный
— результат можно коммитить. Иконка Android лежит в `android/icon_*.png`.
Размеры 24×24 в `.ico` намеренно нет: rcedit его теряет, и Проводник рисует на
месте иконки пустое место.

## Тесты

Гоняются из исходников, в контейнере:

```bash
tools/docker/build-game.sh --test-only
```

- `tests/logic_test.gd` — ввод, опечатки, сложность, детерминированно.
- `tests/profiles_test.gd` — меню игроков: создание, вход, удаление, переключатель
  «все клавиши», возврат по F2, утечка игровых клавиш в открытое меню.
- `tests/chase_test.gd` — инвариант погони: живой цикл со случайным вводом, на
  каждом кадре проверяется, что ёж не оказался впереди зайчика.
- `tests/shot_driver.gd` — съёмка кадров анимации, запускается с окном на
  виртуальном дисплее: `tools/docker/build-game.sh --shot`.

Все три теста обязательны к запуску. Тест, который ни разу не падает на
сломанном коде, бесполезен: правя геометрию погони, сначала ломаем правило
руками, убеждаемся, что `CHASE_TEST` это ловит, и только потом ставим
исправленное.

В тестах перед `add_child` обязательно ставятся `skip_menu = true` и
`all_keys_override = 1`: иначе тест упрётся в меню игроков, а не в проверяемую
логику.

## Экспорт

Пресеты в `export_presets.cfg`: Windows, Linux, macOS, Android. Файл в
репозитории — источник правды для CI, Godot дописывает туда свои ключи при
сохранении из редактора, лишние не мешают. Тонкости (ASCII-only в строках
версии для Windows, `.zip` вместо `.dmg`, ключ подписи Android через переменные
окружения) расписаны комментарием в самом файле.

`tests/*` и иконки чужих платформ исключены из пакета через `exclude_filter`.
У Windows и Linux включён `embed_pck`, чтобы игроку доставался один файл, а не
пара «исполняемый файл + .pck».

CI: `.github/workflows/release.yml` собирает образ из `tools/docker/Dockerfile`
и зовёт `tools/docker/build-game.sh --all`; теги вида `v*` публикуют релиз.
