# AGENTS.md

Правила работы в этом репозитории. Обязательны для всех агентов и контрибьюторов.

## 1. Зависимости — только изолированно, никогда в систему

- Запрещено устанавливать что-либо в системный Python или ОС:
  `pip install --break-system-packages`, `sudo pip install`, `apt install python3-*` — нельзя.
- Python-утилиты (gdtoolkit, линтеры) — только в `.venv` внутри репозитория:
  `python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements-dev.txt`
- **Всё запускается в контейнере.** Единственное исключение — запуск собранного
  бинарника игры, чтобы автор мог погонять. Ни сборка, ни тесты на хосте
  не запускаются.
- **Экран автора (`:0`) — только для игры и только по его просьбе.** Никаких
  тестовых окон, терминалов и пробников там не открывать: автор их закрывает
  как мусор. Всё тестовое — на виртуальном `:99`.
  - Сборка и экспорт игры: `tools/docker/build-game.sh`, образ
    `mbt-godot` собирается из `tools/docker/Dockerfile` (поверх
    `barichello/godot-ci:4.3`). Тот же Dockerfile и тот же скрипт
    использует CI, правила сборки не должны расходиться.
  - Настроек Android (JDK, SDK, ключ подписи) в системе нет: их
    подставляет `tools/docker/mbt-godot-env.sh` на старте контейнера.
- В систему (`/usr`, `apt`) — ничего.
- Временные файлы — в `/tmp/opencode/`, не в общие системные пути.
  Учти: `/tmp` у автора — tmpfs в RAM, он **обнуляется при перезагрузке**.
  Всё, что должно пережить перезагрузку, держим в `tools/`: там лежат
  export templates (1.7 ГБ), бинарь движка и хелперы визуального стенда.
  Правило «важное не в `/tmp`» сейчас особенно строгое: там жил и был
  потерян ключ pollinations и 8 кадров AnimateDiff.
- `.venv/`, `game/dist/`, `game/.godot/` — в `.gitignore`, в коммиты не идут.
  `tools/` в `.gitignore` целиком, кроме `tools/docker/`, `tools/icons/`
  и `tools/x11test.py`: эти три в репозитории, остальное пересоздаётся.
- История: в начале сессии `gdtoolkit` был однократно поставлен мимо `.venv`
  (в user-site), затем полностью откачен (`pip uninstall`, проверено).
  Дальше — только `.venv`.

## 2. Структура

- `main.py` — удалён, pygame-прототип больше не нужен.
- `game/` — игра целиком: Godot 4.3, десктоп Windows/Linux/macOS и Android.
  - `game/scenes/main.tscn` + `game/scripts/main.gd` — игровой экран.
  - `game/scenes/menu.tscn` + `game/scripts/menu.gd` — меню игроков.
    Скрытое меню клавиш не видит, иначе перехватывает ввод раньше игры.
    Список игроков живёт в двух раскладках: в портрете (`view_h >
    view_w`) — карточки во всю ширину, на широком экране и десктопе —
    таблица с колонками (решение 10.2026: в портрете шесть колонок
    выжимали имя в многоточие из двух букв). Карточка: имя крупно во
    всю ширину, ниже строка статистики, ниже — три равные крупные
    кнопки «Про» | «Ё» | ✕ (крестик крайний справа: опасное действие
    не спутаешь). Каждый ряд свой, подрезать имя не о чем. Шапки
    колонок в карточках нет, поэтому пояснение галки даёт само
    переключение чипа (`hint_header`).
    **Размеры кнопок — палец, а не платформа** (автор 16.10.2026: «в
    мобильной вертикальной версии кнопки Про, Ё и крестик правильных
    удобных для мобильника размеров, а кнопки новый игрок и без профиля —
    нет»). Правило общее для обоих рядов — `_card_btn_at`/`_btn_h_at`:
    `72 × масштаб`, пол `_TAP_MIN` (64 px), потолок 132. `_finger()` решает
    не по платформе, а по форме окна: `view_w < 700` — палец даже на
    десктопе (автор гонял игру в портретном окне; раньше ряд внизу был
    `52 × k` и на 412 px экране давал 49 px высоты). Ширина трёх чипов в
    ряд: поля карточки сжимаются только тогда, когда без них кнопка уже
    не под палец, иначе чипы уезжают под зайчика и к самому краю.
    **Состояние флага — знак и своя заливка** (автор 16.10.2026: «включение
    и выключение кнопки про никак не отличается», а «Ё закрашивается в
    цвет фона выделения строки — выделение внутри выделения»). В карточке
    (`_card_chip`): включено — «✓ Про» / «✓ Ё» на `chip_on_sb` (это
    `Ui.ACCENT_*` — тот же синий, что у включённой клавиши в игре; день
    `#a9c6ec`, ночь `#8ab4e0`, подпись `Ui.ACCENT_INK`), выключено —
    пустая рамка `box_sb` и
    подпись приглушённая. Раньше включённый флаг красился `row_sb` — тем же
    жёлтым, что фон выделенной строки. Выделение колонки с клавиатуры —
    ТОЛЬКО ободок `chip_focus_sb` поверх заливки состояния (прозрачная
    панель вместо заливки снова проглядывала жёлтым), и цвет ободка — ПО
    ПОДЛОЖКЕ: `Ui.FOCUS_DARK` на светлом чипе и жёлтой строке,
    `Ui.FOCUS_LIGHT` на тёмной ночной рамке (одним цветом было 1.1:1).
    На узкой карточке
    кегль ужимается под «✓ Про» — резать подпись нельзя, иначе состояние
    не читается.
    **Размер карточек — от ширины экрана (`_card_k`), а не от `k`.**
    `k` на телефоне растёт от плотности (до 2.5), и карточка из него
    съедала пол-экрана текста; доля экрана (34 кегля на 600 px ширины,
    потолок кнопки 132 px, пол 64 px) читается на любом телефоне.
    Длинное имя ужимается под ширину (`_card_name_fs`, потолок
    ужимания 60%), а не режется многоточием: имя игрока — главное в
    карточке.
    **Список листается.** Игроков бывает больше, чем влезет: раньше
    двенадцать карточек ужимали весь интерфейс до нечитаемого (жалоба
    автора 10.2026: «в портрете всё мелкое»). Теперь карточки
    растягиваются на окно списка (`_card_fill`, потолок 1.35), а лишнее
    уходит в прокрутку: `_list_rect` — окно, `_list_max_scroll` — ход,
    `_list_top` — по центру, когда влезло всё. Палец тянет список
    (`_input`: порог `DRAG_MIN`, дальше это уже не тап), колесо мыши
    тоже; тап по листаемому списку отложен до отпускания, иначе жест
    успевал бы выбрать игрока. Стрелки держат выбранного в окне
    (`_scroll_to_sel`). Уехавшую карточку срезает маска
    (`_draw_list_mask`) — список рисуется ДО шапки, иначе маска закрыла
    бы заголовок. Пояснение к галочке (`_chip_hint_y`) в карточках —
    одной строкой над полем ввода, внутри окна списка: под прижатым
    к экрану низом для него места нет, и там своя клавиатура (ловил на
    кадре «name-field»: текст ложился на верхний ряд клавиш).
    **Низ прижат к экрану:** `_buttons_y` считается от `_menu_eff_h()`,
    а когда список короткий — сразу под ним, иначе на высоком окне дыра
    снизу. Отдельного поля ввода НЕТ (имя правится в строке списка), так
    что ряд кнопок (`_btn_row`) упирается в низ экрана, и палец до него
    дотягивается всегда. Таблица тоже листается: в альбоме двенадцать
    строк так же не влезают, окно списка и прокрутка общие (`_list_rect`,
    `_list_max_scroll`).
    **Выбор, игра и создание** (автор 16.10.2026, переломлено 17.10.2026).
    Кнопки «Играть» внизу больше нет. Теперь **прямой тап по строке
    ИГРАЕТ** (`_tap` шлёт `chosen` сразу; автор 17.10.2026: «кликаю по
    своему имени в списке — зайчик трясётся, но игра не начинается!» —
    старое «тап только выделяет, игра по дабл-клику» дожило до первого
    же собственного клика автора). Дабл-клик (`_tap_play`, `double_click`)
    и Enter по выбранному играют так же; галки и крестик строки стоят
    раньше строки в `_input`, тап по правке остаётся в правке. Зайчик:
    `_bunny_jump` молчит, когда цель не изменилась, — повторные прыжки
    «по месту» держали его в дрожи при кликах по одной строке. Внизу
    ряд «+ Новый игрок» (`_new_tap_rect`) и «Без профиля»
    (`_guest_tap_rect`): под пальцем — ДВА полных ряда (`_btn_rows`,
    `_btn_row_rect(j)`), на мыши — один ряд пополам. Постоянного пункта
    «создать» в списке нет — создание кнопкой или Insert, строка ввода
    transient и только на время правки.
    **Кегль подписи кнопки — от её ВЫСОТЫ** (автор 17.10.2026: «кнопки
    стали достаточно крупными, но текст в них МЕЛКИЙ» — кегль был свои
    26k, а в 50/50 ряду ужатие по ширине роняло его до 13px на кнопке
    64px). `_button_fs`: 45% высоты, пол по ширине 24k под пальцем /
    10 на мыши; ширина оставшегося духа — из двух полных рядов. Держит
    `_part33_tap_and_bunny` (ряды, кегль, тап-игра, заяц); кегль
    ловится проверкой «fs ≥ 45% высоты − 1», снятая высота краснеет,
    а снятый пол — нет: пол защищён 24k-гвардом в `_button_fs`.
    **Свап — полный ход, якорь только у клавиатурной навигации**
    (автор 17.10.2026: «список то прокручивается свапом, то заморожен
    и не двигается вообще»). Правило 16.10 «выбранный в окне ЦЕЛИКОМ»
    (`_focus_scroll_bounds`) зажимало ДРАГ в ноль: при выбранной верхней
    строке hi = b0.y − view.y = 0 при живом max_scroll — палец бессилен,
    а при другом sel свап ехал. Заметно только на телефоне, где каждый
    старт сверху. Теперь драг (мышь и палец) и флинг клампятся
    `_scroll_free` — [0, max] без фокусных добавок; колесо, стрелки,
    `_scroll_to_sel` и `open()` держат якорь по-старому. В меню-тестах
    «якорь держит при drag» перевёрнут в «drag scrolls even with the
    top row selected» + пальцевая версия (_drag_finger, ScreenDrag —
    на телефоне эмуляции мыши нет).
    **Маска списка — до края экрана, не до кнопок** (автор 17.10.2026:
    «список может выходить за границы своей формы и оказываться под
    кнопками»). Окно списка кончается над блоком кнопок, а строки рисуются
    натурально; маска (`_draw_list_mask`) раньше красила [окно, _buttons_y]
    — щель между рядами, зазор по бокам и у нижнего края пропускали
    край карточки. Теперь маска красит от низа окна до view_h; кнопки
    рисуются позже и поверх маски.
    **Верхняя панель игры — палец даже в альбоме** (автор 17.10.2026:
    «верхние элементы... в горизонтальном становятся еле читаемыми и
    кликабельными» — бейдж уровня, имя игрока, кнопка ≡). k в игре меряет
    от эффективной ВЫСОТЫ, и в альбоме (экран 540 units при клавиатуре
    или 1080 physical) падал до ~0.9: кегль 26k ≈ 23 px, кнопка ≡
    50×43. Полы по ПЛОТНОСТИ, не по k: `_bar_fs` — кегль ≥ 22dp
    (`Ui.dpr()`, только не-десктоп), бейдж и заголовок h ≥ 1.55·fs,
    `_players_rect` ≥ 44dp. Десктоп не меняется (там is_desktop() отводит
    полы). Заголовок — не про запас 220k, а от ФАКТИЧЕСКОГО края кнопки
    ≡ (`_players_rect.position.x − _badge_rect.end.x`), прямоугольник
    сохраняется в `_title_rect`. Держит `_bar_floors` в logic_test
    (альбом 2280×1080 dpr2, портрет 1080×2280, десктоп — прежние 26k/56k).
    **Уголки маски — по дуге рамки** (автор 18.10.2026: «теперь, когда
    вписок не вылазит за нижнюю грань, он стал вылезать за верхнюю»).
    Маски (верх `_draw_top_mask`, низ `_draw_list_mask`) прямоугольные,
    а рамка окна скруглена (радиус 12 в panel_sb): ряд у самого края
    торчал из-под дуги — в зазоре между дугой и прямой линией маски был
    виден жёлтый фрагмент карточки (подтверждено кадром vis-menu-10:
    чип «Про» вне дуги). `_mask_pod` закрашивает по бумаге квадрат
    r×r минус четверть диска — полигональная дуга тем же радиусом, что
    у рамки (`_list_frame_radius`); у обеих масок заглушки по самим
    углам. Радиус в полигонах обязан совпадать с рамкой — иначе щель
    возвращается.
    **Компактный список — мобильный портрет** (автор 18.10.2026:
    «в мобильных версиях в вертикали — компактное представление каждого
    пункта, без кнопок и в одну строку; однократное нажатие на
    невыделенный пункт разворачивает его до состояния с кнопками.
    Повторное нажатие по уже выделенному (не по кнопкам) — запуск игры,
    такое же, но с удержанием — переименование»). `_compact()` =
    `_cards() и _finger()`: свёрнутая строка — имя слева (ужатие до 60%
    кегля, как в карточке) и статистика справа приглушённо, высота —
    строка с воздухом, пол TAP_MIN; `_row_h` — карточка (`_card_h`) у
    выбранного и правимого ряда, `_compact_h()` у остальных; позиции
    рядов — `_row_y` (сумма высот предыдущих), в `_list_all_h` и
    `_row_box_at` та же мера: расширение одного ряда сдвигает всё ниже.
    Чипы существуют ТОЛЬКО в развёрнутом ряду: рисуются только там, и
    тапы (`_tap`) их ловят только у sel/editing — тап по зоне чипа
    свёрнутого ряда разворачивает строку, флаг не трогает. Долгое
    нажатие (`ROW_PRESS_T`) на развёрнутом правит имя, на свёрнутом —
    только разворачивает (тап после этого проглатывается). Дабл-клик
    (`_tap_play`) играет напрямую по любому ряду. Держит
    `_part28_cards` (чипы только в развёрнутом, тапы через разворот,
    дабл-тап по свёрнутому играет, зона чипа свёрнутого не трогает
    флаг), `_part33_tap_and_bunny` (первый тап выбирает без игры,
    второй играет; заяц после разворота успокоен — «same-row hop»
    сверяется на долетевшем), `_part29` (тап после драга по свёрнутому
    ряду разворачивает, не играет). Кэш `_list_rect` включает sel в
    ключ (`_lr_sel`): высота списка зависит от выделения.
    **Порядок списка стабилен.** Сортировка по `last_played` двигает
    только `touch()` (факт игры). `save_profile`, `_toggle_*`,
    `_rename_user`, `_create_user` порядок не трогают: иначе переключение
    галочки уводило бы выделение из-под пальца.
    **Создание = строка списка.** На пустом списке открывается строка
    создания (`_reload` → `_start_edit(0)`), а не голый `input_active`:
    поле рисуется в строке, и без строки набираемое имя было не видно
    вообще (первый запуск). Правка держится ровно на своей строке:
    создание — `editing == users.size()`, переименование — существующая;
    всё прочее (`_drop_edit` из `_reload`) — висячая правка, она
    сбрасывается молча и БЕЗ `_relayout` (тот берёт размер из вьюпорта, а
    в тестах он 64x64 и сбивает выставленные руками величины). Галочки
    строки правки рабочие: тап по «Про»/«Ё» в `_tap` переключает ждущие
    `input_all_keys`/`input_yo_strict` (иначе нарисованный флаг был бы
    декоративным), и оба гаснут вместе с правкой (`_cancel_edit`).
    Пустое имя при создании правку НЕ закрывает — человек ещё набирает.
    **Выход из любого состояния.** F2 в правке имени отменяет её и
    возвращает в игру: иначе chaos-тест находит тупик (правка съедала
    F2, а выхода из меню не было).
    **Прокрутка: цель и догон.** Колесо и стрелки двигают `_scroll_target`,
    `_process` догоняет его (`MENU_SCROLL_CHASE=18`, добег
    `MENU_SCROLL_SNAP=0.05`), палец ведёт 1:1 и на отпускании отдаёт флинг
    (`_fling_v`, порог 240 px/с). Границы — не `[0, max]`, а
    `_focus_scroll_bounds`: выбранная строка (а при правке — строка ввода)
    обязана быть в окне ЦЕЛИКОМ. Якорь меряется боксом `_row_box_at`, а не
    линией строки: в таблице бокс на `38k` выше линии, и по линии верх
    строки прятался под маску. Тап за окном списка до строки не доходит
    (`_row_shown`) — как и глазом, маска режет. Держит `menu_scroll_test`
    и `_part29` (там, где нужна геометрия после догона, тест крутит
    `_process` через `_settle_scroll`: в headless кадров нет).
    **Верхняя панель** (автор 15.10.2026: «“Кто играет?” на самом верху
    с кнопкой, и тему тоже сверху справа»): слева «Обновления», по
    центру заголовок, справа солнце-луна (`_bar_h`, `_title_*`,
    `_night_tap_rect`). Ничего ни на что не наезжает: держит
    `_part31_menu_no_overlap`
    (матрица 7 экранов × 0/3/12 игроков × сообщение × ночь).
    **Зайчик — в своей полосе слева от списка** (автор 15.10.2026:
    «не удалять и не уменьшать кролика, отвести под него столбик»).
    Прежде он стоял у заголовка и закрывал имя первого игрока. Размер
    прежний (`76k`), полоса — спрайт + зазор, в таблице вычитается из
    доступной ширины, а не сдвигает левый край (иначе колонки уезжали

    [↔{, ,↔<, `↔~ летят, как все знаки (`Kbd.animates` + `_twin`). Покой и полёт рисуются одной функцией (`_rest`):
    концы перелёта совпадают с покоем, знак не скачет.
    **Девять мест.** У каждого знака ровно один дом из девяти: углы tl
    tr br bl, края t b l r, центр c (автор 10.2026: «у каждой кнопки своё
    место… пусть 9»). Углы — строкой `CORNERS`, края «-_» и «+=» — таблицей
    `EDGE` (знак с шифтом сверху, основа снизу: столбик по центру, как
    требовал автор). Центр — дом служебных клавиш (шифт, стереть, ввод,
    глобус) и временная стоянка набираемой подписи. Исключений для
    отдельных клавиш в механике нет: все летят одним перелётом дом↔центр
    (`animates` + `_rest`). У подчёрка оптический подъём на 0.3 кегля
    (висит на базовой линии — свойство знака, действует везде).
    **Нажатие.** Нажатая клавиша вспыхивает отдельной заливкой (`kb_press`
    + `KB_FLASH_T`), чтобы человек видел, что попал именно в неё, а при
    промахе — что мимо. Верный ввод — **зелёным**, опечатка — **красным**
    (`_verdict`, тот же сравниватель `_eq`, что у ввода), и это работает
    и для тапа по доске, и для физической клавиатуры (там вспыхивает та
    же клавиша на доске). Затухание не мгновенное: alpha заливки падает
    вместе с таймером (`_press_sb`), последние кадры почти прозрачны.
    ВАЖНО: когда таймер доходит до нуля, подсветку надо **погасить
    последним кадром** (`kb_press = ""`) — иначе кадр с заливкой уже
    отрисован, следующего `queue_redraw()` не будет, и клавиша залипает
    (жалоба автора 10.2026). Держит `_case_press_flash`, брейк — снять
    это гашение. **Шифт не защёлкивается, а ДЕРЖИТСЯ**: нажал —
    загорелось, отпустил — погасло (автор 10.2026). Работает и на доске
    (`kb_held`), и на физической клавиатуре (KEY_SHIFT по нажатию и по
    отпусканию). Внимание: `Kbd.hit()` отдаёт «шифт», а не подпись
    «Shift» — сверять надо с тем, что вернул hit.
    **Автоповтор.** Зажатая клавиша повторяется, как в редакторах:
    пауза 0.45 с, дальше каждые 0.06 с (`kb_held`/`kb_repeat_t`,
    `_repeatable`). Повторяются буквы, знаки, пробел и стереть; шифт,
    глобус и ввод — нет. Живые тапы идут через `_own_press(pos, true)`,
    прямые вызовы из тестов удержания не ставят. Физическое эхо идёт
    тем же путём, но уровни по эху не листаются. Держит
    `_case_key_repeat`.
    **Ввод на доске.** Пока часть букв уровня серая (проходится сама),
    клавиши ↵ на доске нет — вводить нечего. Ввод появляется, когда
    открыт ЦЕНТРАЛЬНЫЙ РЯД букв текста (фывапролджэ, `HOME_LETTERS`),
    а не в самом конце уровня (автор 10.2026: «разблокировал бы клавишу
    энтер после того, как разблокирован весь центральный ряд букв»).
    **Центральный ряд — по ЭТОМУ тексту** (`_refresh_home_chars` +
    `HOME_LETTERS`, `home_chars`), и ввод ↵ разблокирован ровно он
    (`_enter_unlocked`, автор 16.10.2026). Пока ряд закрыт, перенос
    исходника проходит СЕРЫМ АВТОПРОПУСКОМ (`_advance` не ставит
    `need_enter`), иначе новичок с «а, о, пробел» упирался бы в ↵ на
    первых же строках — до того, как выучил ряд. Сетап текста в тестах
    обязан звать `_refresh_home_chars()`: без него ввод судил бы по
    буквам ПРЕДЫДУЩЕГО уровня. Держит `_case_grey_first_line` в
    `combo_test` (обе стороны правила; со снятым автопропуском краснеет
    на трёх проверках).
    В ПРО-режиме («все клавиши») ввод есть падавно. Единственный ↵ на
    всей доске — справа от «э», как настоящий Enter; снизу его нет.
    **↵ только на переносе строки ИСХОДНИКА** (автор 13.10.2026: «где
    в оригинальном файле был перенос строки — диалоги, концы абзацев,
    стихи» — «их не надо ни исключать, ни добавлять»). Предложения
    внутри абзаца СКЛЕИВАЮТСЯ в сплошной текст, как в Word: видимый
    разрыв строки — либо перенос по ширине (мягкий, курсор едет сам),
    либо конец абзаца (жёсткий, ждёт ↵). Каждое предложение своей
    строкой больше не кладётся: это были ДОБАВЛЕННЫЕ переносы, из-за
    которых «перенос есть, а энтер не нужен». Признак «здесь был
    перенос» рождается в `Texts.file_units` (конец физической строки
    файла) и едет по вёрстке: `load_fragment` → `B.fit_marked` (склейка
    мягких + резка по словам) → `main.line_hard`/`line_glue` →
    `B.reflow` (при повороте экрана мягкие строки склеиваются обратно в
    тот же абзац; куски разрезанных посередине слов клеятся без пробела
    через `line_glue` + флаг остатка `cur_glue`, иначе внутрь слова
    вставляется пробел — ловила матрица: «принадлежала ;») →
    `_hard_line`. **Вёрстка режет под ЛЮБУЮ ширину** (порог 36 убран
    14.10.2026): раньше широкие экраны отдавали предложения как есть, и
    длинные строки вылезали за карточку — хвоста не было видно, а маркер
    стоял вне карточки (жалоба автора 13.10.2026, поймано числом:
    «row 5 has 93 chars, fits 70», «1840 px, card ends at 1455»).
    Сколько знаков влезает — считает `_max_chars`, проверка — числом
    (`_text_geometry`: знаки И пиксели каждой строки, маркер внутри
    своей полосы и карточки в трёх точках строки и в ожидании переноса
    на жёсткой строке; `_cursor_rect` вынесена из `_draw`).
    **Пробел на переносе — клетка** (автор 14.10.2026: «при автопереносе
    сам пробел надо нажимать, как в редакторе»): мягкая строка кончается
    «слово » (на знак шире лимита — запас колонки уже в `_max_chars`),
    игрок жмёт пробел, дальше курсор едет сам; подсказка на нём —
    половина пробела по руке (как на обычном пробеле). Съеденных
    пробелов больше нет (`drops` всегда нули, остаток убран вместе с
    понятием); `glue` — только куски разрезанных слов. Держит
    `_reflow_wrap_space` + `_case_wrap_auto` (пробел считается,
    подсказывается) + матрица `end_test` (мягкие не-glue строки кончаются
    ровно одним пробелом, жёсткие — без, склейка даёт абзацы буква в
    букву, ширины 12–70).
    Ось текста — со съеденными пробелами везде (`B.line_bases` с
    `drops`, как `logical_cells`): иначе та же буква имеет разные
    координаты до и после пересборки и погоня рвётся (ловил
    `_case_relayout`: зазор 46 → 76 при зайце на той же букве).
    А точные шаги («откат ровно на символ», «стопка символ в символ») —
    про ВИДИМЫЕ клетки: в тестах своя клеточная мера `_cx` (в combo,
    marks, chase), для погони/диапазонов/доли — `_lin`/`_ax`.
    Курсор и метки на стыке строк едут на начало следующей
    (`B.cell_for`); конец уровня — всё равно конец. Держит
    `_reflow_wrap_space` + `_lin_stable` в logic.
    Ёж переживает пересборку вместе с текстом (`_remap_enemy` в
    `_reflow_text`, только в партии): сквозное смещение сохраняется,
    строка правится таблицей; в туннелях (до/после строки) — тоже.
    Ежа ставят через таблицу (`_enemy_at` в combo: смещение глобальное,
    а строка — нет; раньше база прибавлялась дважды). Замер релэута —
    после успокоения героев (60 кадров + контроль сходимости), а не на
    первом: иначе ловит середину перелёта. Ёж в той же строке, что заяц
    (6 клеток позади в строке): зазор иксами осмыслен только в одной
    строке — было «-15» из соседних строк.
    **Разогрев: гонка начинается с ПЕРВОГО ввода человека** (автор
    17.10.2026: «заяц сразу оказывается во второй, и ёж начинает
    движение, хотя пользователь ещё не сделал ни одного разогревочного
    ввода»). На уровне, где первая строка целиком из серых букв,
    автопропуск уводит курсор на вторую, `hedge_active` становится истиной
    — и через `START_DELAY` ёж катился по часам, без единой нажатой
    буквы. Теперь флаг `warm_done`: его ставит любой ввод (верная буква,
    опечатка, ↵ — «нажатие услышано»), а разогрев держит **выезд** ежа
    (`hedge_active`), а не физику: раз выехал — едет без остановок, иначе
    «ёж стоит» стало бы ещё одним состоянием. В обычной игре, где первая
    строка активная, это ничего не меняет — гонка и так начинается после
    того, как заяц уйдёт на вторую строку. Держит `_case_warm_up` в
    combo; на сломанном разогреве (вернуть гейт на движение) краснеет на
    трёх проверках. Брейк — `hedge_active` без `warm_done`, или разогрев,
    который ждёт ПЕРВОЙ ВЕРНОЙ буквы (опечатка тоже ввод: человек уже
    в игре).
    Заяц встаёт ПОСЛЕ скролла (`_new_level`: сначала `_refresh`, потом
    `_hero_pos`): раньше вставал до, на сотни px мимо при сером
    автопропуске вглубь, и долетал десять кадров.
    Пересборка гасит протухшее ожидание: курсор уже не за концом строки
    → `need_enter = false`, иначе игра стоит с курсором на букве.
    При `need_enter` игра стоит и переход делает только нажатие ввода — с
    доски (`_own_press`) или физическое Enter. Пока ждём, буква не
    печатается, но ошибкой СЧИТАЕТСЯ: счётчик тикает, заяц шагает назад
    откатом (автор 10.2026: «в ожидании энтера можно совершать любые
    ошибки и они не засчитываются»). Метку ставить не на что — курсор за
    текстом; вспышка такой буквы красная (`_verdict` даёт «err»).
    Подсказка зовёт ↵, `↵` на доске есть, а у конца строки, которая
    ждёт, стоит **шеврон «↵»** (`_enter_hint`): приглушённый, с мягкой
    пульсацией, ЗА рамкой курсора (на полторы клетки вправо, иначе
    сливается с ней в пятно). Вне ожидания на экране ничего лишнего.
    Последняя строка текста уровень кончает сама: ждать переноса
    незачем. Backspace на ожидании ОТМЕНЯЕТ перенос, но только к
    НАБРАННОЙ клетке: откат идёт `_last_filled_behind`, как в обычном
    Backspace, а если за курсором нет ничего набранного, ожидание
    ЖИВЁТ и ничего не стирает — серые автопропуски прошла САМА ИГРА,
    откатывать их нельзя (первопричина, а не симптом: редкая строка
    без пробела доводила автопропуск до жёсткого конца и Backspace
    уносил пройденное игрой, вставая в серую клетку — CI 18.10.2026;
    сначала был редуцирован тестовым обходом, потом исправлен в игре;
    ловится строкой руками в
    logic_test: «no-space grey line» и «typed wait»). Держат
    `_case_wrap_waits_enter` (жёсткий перенос, backspace встаёт на
    клетку) и `_case_wrap_auto` (мягкий едет сам, пробел считается) в
    combo, `_text_breaks` + `_text_geometry` в logic (матрица
    `fit_marked`, склейка/рефлоу туда-обратно, признаки по корпусу).
    Брейк — вернуть `need_enter` на ЛЮБОМ конце строки в `_advance` или
    порог 36 в `_fit_to_width`/`reflow`. ТЕСТЫ, набирающие текст, обязаны
    слать ↵ там, где игра его ждёт (хелперы `_type_next`/`_advance_to`,
    `_fresh`).
    **Карточка текста занимает всё свободное место** (автор 14.2026:
    «в горизонтальной набираемый текст точно мелкий», и пустоты есть и
    в портрете, и в альбоме). `_text_free_h` — одна мера на всё:
    эффективная высота минус шапка и полоса снизу. Шапка —
    `_bar_band_h` (низ бейджа и ≡ той же арифметикой, что рисует), а не
    фиксированные 80k: с честными dp-полами панель выросла и
    накрывала первый ряд текста с зайчиком (замер на стенде
    18.10.2026); карточка держится на `_text_top_h` = полоса + зазор,
    в `logic_test._bar_floors` инвариант «card top clears the top bar»
    на длинном уровне (короткий центрируется и перекрытия не видит —
    проба на `_text_top_h`=0 это вскрыла). Полоса снизу — 120k:
    прогресс со счётом 14..26 (счёт справа от полосы, той же строкой —
    подпись под полосой стоила целой строки высоты) и подсказка
    36..100; подсказку резервируем ВСЕГДА, иначе текст дёргался бы на
    кадре, когда подсказка появляется. Верх панели подсказки —
    `_hint_top()` отдельной функцией, а не строчкой в `_draw`: в
    headless картинку не рисуют, а геометрию проверяем числом.
    **Кегль под САМ текст** (`_text_font(chars)`): считается от базовых
    `36k` — сколько строк текст занимает при них и во сколько раз он
    уже меньше комнаты; растёт кегль — растут строки (ёмкость строки
    обратно пропорциональна кеглю), поэтому масштаб берём КОРНЕМ
    (комната ~ кегль²). Один шаг, без итераций и раскачки. Границы:
    36k..72k, ужим по ширине — не уже ~15 знаков в строке. Звать ДО
    переноса (`_new_level` — до `_fit_to_width`) и обязательно там же
    пересчитать `char_w`: старый `char_w` давал строки шире карточки
    (ловил `logic_test`: «row 16 is 638 px wide, card ends at 478»).
    **Интерлиньяж** `_fit_line_h` — точным делением комнаты на число
    строк (округление вниз оставляло целую строку воздуха снизу);
    ужатие ниже 1.8 глифа не даём (шар ежа в зазоре становится
    неразличимым, на чьей он строке), растяжка выше 2.4 — тоже (автор
    14.10.2026: растянутый интерлиньяж «слишком большой»); считается
    ПОСЛЕ пересборки строк (`_layout_text_lines`), иначе делилась бы
    комната по старому числу строк. Короткий текст центрируется в
    свободной высоте (`text_y`), длинный упирается в верх и едет
    скроллом. Видно строк — `_vis_lines`, тот же подсчёт с допуском
    0.001 против float-пыли.
    **Скролл — заранее и плавно** (автор 15.10.2026: «более плавная
    прокрутка, причём заранее, чтобы заканчивая строку видеть
    следующую»). Курсор НЕ в последней видимой строке: под ним всегда
    видна следующая (`first = min(cursor, cursor−vis+2)`; на крошечном
    окне vis=1 lookahead некуда деть — там курсор последний).
    Окно едет не прыжком, а догоняет цель (`scroll_y → scroll_target`,
    18/с, добег 0.5px) — быстрее зайца (12/с), чтобы герои не
    отрывались от букв. Вне партии окно замирает вместе с табло: иначе
    после укола скролл уезжал из-под застывших героев (ловил
    chase_test). `visual_driver` окно не пересчитывает, а берёт
    `vis_first` из игры, иначе сверка врала (метка «за скроллом», хотя
    игра её показывает).
    **Финал без слов** (автор 15.10.2026): «Уровень пройден!» и
    «Ёж догнал!» убраны — исход виден и так, а звёзды лезли на текст.
    Подсветку ↵ на доске держит `_hint_keys` (текст ей не нужен).
    Звёзды — крупные, своим лейблом по центру карточки (`_layout_stars`,
    кегль от её высоты); модалка под карточкой — только статистика
    одной строкой. Первый тап по звезде объясняет балл, повторный по
    той же идёт дальше (иначе звезда по центру съедала бы главный тап).
    `_refresh` обновляет и карточку со звёздами тоже: иначе после
    `_finish` они показывали прошлый уровень (ловил тест).
    Держит `_geo_fill` в `logic_test` (числом, на матрице экранов):
    кегль в границах, плотность строки 1.8..2.4, текст на естественном
    шаге занимает ≥ 70% карточки (главное правило — иначе кегль мал, а
    разницу съедает интерлиньяж), короткий уровень не растягивается и
    не липнет к верху, подсказка не наезжает на полосу и не уходит под
    край. Ломал руками: кегль без роста, снятый потолок интерлиньяжа и
    подсказка на полосе — краснеет каждое.
    **Курсор всегда на букве.** Единственное исключение — ожидание
    переноса (курсор за концом строки с `need_enter`). Держит инвариант
    в `_common`/`_invariants` combo, marks и chase на КАЖДОМ кадре
    (автор 10.2026: «покрыть сценарии сдвига курсора тестами»).
    Координаты букв — ОДНА мера на всё (`_cell_x`: клетка = pos ×
    char_w). char_w — предельный advance в строке (целое(64) минус
    целое(1) на 63), а НЕ одиночный замер: одиночный глиф шейпер
    округляет наружу, и сумма одиночных расходится с целым на
    ~пиксель/знак (замерено 720 против 687 на 60 знаках) — маркер
    уползал от букв с накоплением к концу строки (жалоба автора
    13.10.2026). Второго пути измерения нет: вёрстка, маркер (`_cursor_cx`,
    `_cursor_rect`), заяц, шеврон и сама отрисовка (`_draw_rows` рисует
    каждый глиф в его клетку, построчных RichText-лейблов больше нет)
    считают одно и то же. Держит `_marker_cells` (линейность char_w на
    трёх кеглях + центр и рамка маркера ровно на клетке). Брейк —
    замер префикса целой строкой в `_cursor_cx`.
    **Рисочки.** На клавишах «а» и «о» — тактильный рисочек у нижнего
    края: на настоящей клавиатуре это клавиши под указательными
    пальцами, их находят не глядя.
    Tab, Caps, Shift и прочие служебные — тоже заблокированы (в наборе
    не участвуют, подпись приглушена, тап мимо).
    Стереть вбирает остаток ряда до края доски (~2.5u): тест держит
    диапазон 2–2.75 цифры (автор 10.2026: «бекспейс не достаточно широк,
    чтобы дотягиваться до края»).
    **Геометрия.** Питч ОДИН на все ряды: цифры 1..0,-,= — того же
    размера, что буквы (автор 10.2026). Ширины модификаторов — стандарт
    ANSI в единицах питча: Tab 1.5, Caps 1.75, левый Shift 2.25; правый
    край вбирает остаток (стереть ≥ 2u, ввод ≥ 1.2 питча, правый шифт
    ≥ 32 px). Ряды стоят от левого края, ступеньки — шириной
    модификаторов: буквы на 1.5 / 1.75 / 2.25 питча. Отсюда сдвиг цифр:
    «1» на полпитча левее «й», «ф» на четверть правее «й», «я» на
    полпитча правее «ф» — та же ступенька, что на настоящей клавиатуре
    (автор 10.2026: «ревизия сдвига»). Держит `_stagger`. Меню, как и
    игра, держит доску в 46% высоты (`width_for`), иначе на низком экране
    доска накрывает кнопку «Играть» и тап уходит в клавишу.
    У каждой буквы обе раскладки сразу и почти одного размера (мелкой
    идёт вторая, у букв — 0.66 кегля, у знаков — 0.55). Долгого нажатия нет: у «ё» и «ъ» свои клавиши. Ввод
    на доске листает дальше на финале, а в партии переносит строку
    (см. «↵ только на переносе строки ИСХОДНИКА» выше). Каждый знак текстов обязан набираться (держит покрытие в
    logic_test). На финале клавиатура не прячется: иначе раскладка
    прыгает и табло укола разъезжается.
    Системной клавиатуры, composing-буфера, фильтра дублей и стека снятий
    в коде игры нет; `build-game.sh` это проверяет линтом. Счётчик
    `cfg_loads` следит, что файл не читается в кадре. Мёртвый флаг
    `sys_kb` в старых профилях вычищает `drop_legacy_guest`.
  - `game/texts/{kids,pro}/*.txt` — корпус уровней: 19 детских файлов

## 3. Команды

```bash
source .venv/bin/activate
.venv/bin/gdparse game/scripts/balance.gd game/scripts/save.gd game/scripts/main.gd \
  game/scripts/menu.gd game/tests/logic_test.gd game/tests/profiles_test.gd \
  game/tests/marks_test.gd game/tests/combo_test.gd game/tests/chase_test.gd \
  game/tests/shot_driver.gd game/tests/visual_driver.gd \
  game/tests/menu_driver.gd
tools/docker/build-game.sh --test-only          # десять тестов, параллельно
tools/docker/build-game.sh --all                # тесты + 4 платформы
tools/docker/build-game.sh --preset Android     # одна платформа
tools/docker/build-game.sh --shot               # кадры анимации
tools/docker/build-game.sh --visual             # кадры партии + модель, потом меню
```

Тесты идут параллельно (ядер хватает): шесть быстрых плюс погоня
четырьмя шардами (`-- --shard I --of 4`, эпизоды независимы, сиды
разные, бюджет делит 120 эпизодов; слияние в `run_chase` суммирует
счётчики и держит те же пороги). Тяжёлые тесты шардируются изнутри
тем же флагом (`run_sharded`: combo/marks/end берут каждую N-ю работу
по кругу; у каждого шарда свои контейнер, лог и дом). Сценарий обязан
быть независимым: начинать с чистого уровня (`_fresh`) и не читать
чужих меток/курсора (ловил: `own_kbd_fits` без `_fresh` падал на метке
прошлого сценария). У каждого
теста и шарда свой контейнер, лог и дом (`user://`-профили общие
не делят). Общее время определяют самые долгие шарды (минуты), а не
сумма (~25 мин).

Тесты: `LOGIC_TEST` (логика ввода), `PROFILES_TEST` (меню игроков),
`PERF_TEST` (бюджет кадра), `MENU_SCROLL_TEST` (выбранная строка в окне),
`MARKS_TEST` (метки и координаты героев), `COMBO_TEST` (комбинации
  событий: IME, автозамена, Backspace, шторм ошибок, конец уровня),
  `CHASE_TEST` (инвариант погони),
`THEME_TEST` (контраст палитры), `UPDATE_TEST` (обновление),
  `END_TEST` (уровень проходится на узких экранах). Все десять
  обязательны к запуску. Сторож в `build-game.sh` ловит и мёртвый код: системная клавиатура,
`?123` и долгое нажатие ДЛЯ НАБОРА (по его именам `LONG_PRESS_MS`,
`_lp_*` — у меню своё долгое нажатие на строке, `ROW_PRESS_T`, и общая
приставка `LONG_PRESS*` глушила сборку).
Тест, который
ни разу не падает на сломанном коде, бесполезен: правя геометрию погони,
сначала ломаю правило руками, убеждаюсь, что `CHASE_TEST` это ловит, и только
потом ставлю исправленное. Каждый тест идёт под сторожем `build-game.sh`:
потолок по времени и мгновенный красный статус при `SCRIPT ERROR` (без
сторожа сломанный тест не падает, а молча крутится до лимита кадров).

`gdparse` из requirements-dev новее движка и НЕ ловит несоответствия API:
`KEY_GO_BACK` и `virtual_keyboard_show()` без аргументов он проглотил,
а Godot 4.3 на них упал с Parse Error. Новые вызовы DisplayServer и ключи
`KEY_*` сверять с 4.3 (grep по бинарю в образе), а не с gdparse.

В Godot-конфигах (`project.godot`, `export_presets.cfg`) комментарии только
через `;`: строки с `#` парсер склеивает в имя соседней настройки, и движок
видит дефолт. Так умер автоповорот: `screenOrientation` в APK остался
ландшафтным. Проверяется байтом: `aapt2 dump xmltree ... AndroidManifest.xml`
и `ProjectSettings.get_setting` в headless-прогоне.

Ориентация следует за телефоном (`window/handheld/orientation=6`), а
`_own_rect()` считает клавиатуру от ШИРИНЫ: в альбомной ориентации клавиши
выходили ВЫШЕ экрана (2340x1080 → 1128 px), раскладка схлопывалась в
полоску у верхнего края, текст оставался огрызком (визуальный прогон
10.2026, кадры «landscape»). Теперь высота ограничена долей экрана, а
лишнее убирается шириной: клавиши квадратные, полоса по центру. Держат
`_case_own_kbd_fits` (четыре размера экрана) и кадры 21-22 драйвера.

Открыть `game/` в Godot 4.3+, запуск — F5. Релизы: `git tag v0.0.18 && git push --tags`
(тег обязан совпадать с `config/version` в `game/project.godot`, CI это
проверяет).

**Версия в артефактах.** Godot берёт номера из `game/export_presets.cfg`
и пишет их как есть: там стояли свои 0.0.9 (Windows/macOS) и 0.0.10
(Android), и с 0.0.10 они не двигались — в APK был `versionName=0.0.10`
при `config/version=0.0.17`, телефон показывал «0.0.10» на любой сборке.
Теперь `build-game.sh` (`stamp_version`) ставит версию проекта во все
платформы перед экспортом и возвращает пресет как был (`trap`), дерево
остаётся чистым. Проверяется байтом после сборки:
`aapt2 dump badging game/dist/ModernBabyType.apk | grep package` —
`versionName` должен совпадать с тегом.

## 2а. Что перенос строк делает с клетками (обязательно держать)

- **Логические смещения — в пространстве «все пробелы».** Разрывы
  выкидывают пробелы, и старые смещения (с пробелами) нельзя искать в
  новой таблице (без них): всё уезжало на число выкинутых пробелов.
  `B.logical_cells` строит таблицу с учётом drops, `B.reflow` принимает
  старые drops, `line_drops` едет параллельно `display_lines`, а
  `_remap_cells` переносит passed/errors/typed_cells (все три — раньше
  typed_cells оставался на старых клетках). Пройденный пробел, попавший
  ровно на разрыв, законно исчезает: такой клетки больше нет, и
  `end_test` сверяет буквы, а не штуки. Держат `_case_reflow_typed_cells`
  и флаки-тест menu_roundtrip (меню прячет клавиатуру → релэут → рефлоу).

## 2б. Что файл на диске может принести (обязательно держать)

- **Значение профиля — не обязательно словарь.** Правка руками или
  обрыв записи на телефоне дают в разделе число, а не словарь. Раньше
  чтение падало на касте — игра не доходила до экрана. Теперь
  `load_profile` проверяет тип и отдаёт дефолты. Держит `_part25`
  (`profiles_test`): мусор вместо файла, профиль-число, поля чужих
  типов — игра поднимается гостем и играбельна.
- **Уходя из обновления, отменяй закачку.** Кнопка «Не сейчас» есть на
  экране, но с клавиатуры до неё было не дойти (только Enter; Esc уходил
  из ИГРЫ), и отказ во время закачки ничего не отменял: файл докачивался
  и установщик вылезал поверх игры. Теперь Esc/N гасят модалку, а
  `_upd_no()` зовёт `cancel()`. Держит `_part26`.
- **Esc ведёт из кона в меню, повторный в меню — полный выход**
  (автор 10.2026). В меню выход идёт через флаг `quit_requested`
  (настоящий quit убил бы тестовый процесс — прецедент
  `all_keys_override`). Держит меню-раундтрип в combo и `_part26`.

## 3а. Что телефон делает сам (обязательно держать)

Телефон — не только экран, но и источник событий, которых нет на
десктопе. Каждое из них уже стоило бага:

- **Уход в фон / звонок / тяжёлый кадр.** После такого движок отдаёт
  дельту в секунды. Без потолка `MAX_FRAME_DT` (`_process`) ёж за ОДИН
  кадр проезжал десятки символов: ребёнок возвращался к «Ёж догнал!»,
  ничего не нажав. Проба 10.2026: dt = 0.5, 2 и 8 секунд — мгновенный
  проигрыш. Держит `_case_frame_spike`.
- **Профиль — файл на диске.** Его правят руками, он бывает побит или
  достался от другой версии. `_start_game` приводит значения к
  допустимым (`enemy_cps` в [MIN_CPS, MAX_CPS], `difficulty` по набору
  букв, `wins_in_row` < WINS_TO_LEVEL_UP, `ema_acc` как доля). Без
  этого `enemy_cps = 1000000` из файла убивает на первом кадре, а
  значение переписывается обратно при каждом конце уровня: из такого
  тупика не выйти ни одной победой. Держит `_case_broken_profile`.
- **Игра просит то, что нечем нажать.** «ё» и «ъ» на своей клавиатуре
  есть только долгим нажатием. Если подсказка молчит, ребёнок жмёт «е»
  и копит красные метки: «Долго жми [Е] → [Ё]» (`_hint_parts`, держит
  `_case_yo_hint` и кадр 24 драйвера).
- **Знаки — как на настоящей клавиатуре.** Мы учим человека реальной
  клавиатуре, поэтому «:» это Shift+6, а не слой ?123: подсказка
  («Жми: [Shift] + [6]») и подсветка учат именно этому
  (`Kbd.shift_digit`/`digit_for`, `_own_press` гасит шифт после знака).
  Слой знаков остаётся запасным путём. Держит `_case_sym_layer_hint`
  и кадр 25 драйвера.
- **Подсказка считается каждый кадр.** Не проверять наличие клавиши
  через `Kbd.buttons()`: это пятьдесят выделенных Rect2 и словарей на
  кадр. `Kbd.has_key()` смотрит только подписи рядов, а обычные буквы
  отсекает `Kbd.is_plain_letter()`.
- **Два пальца на доске.** Godot превращает касание в мышь только для
  ПЕРВОГО пальца (`input_devices/pointing/emulate_mouse_from_touch`), и
  раньше второй палец не доходил вовсе: «шифт зажимается и на букву
  реакции уже нет» (автор 17.10.2026) — регистр набирался только на
  живую клавиатуру. Поэтому `InputEventScreenTouch` слушается САМИМ в
  `_input` игры и меню: палец → `_own_press`, а по отпусканию гасится
  ровно та клавиша, которую держал ЭТОТ палец (`_touch_keys` по индексу).
  Мышиное эхо того же касания отсекается счётчиком пар, а не по часам:
  `one touch → at most one echo` (`_echo_pending`), потому что на
  телефоне между касанием и эхом может пройти и сотня миллисекунд, и по
  часам настоящий тап проскочил бы в обработку дважды. Держит
  `_case_touch_multitouch` в `combo_test` (с выключенным мультитачем
  краснеет на трёх проверках, с выключенным подавлением эха — на
  «буква набрана дважды»).
- **Один тап — один ввод, эмуляция мыши ВЫКЛЮЧЕНА.** Первое
  исправление («два пальца») оставило эмуляцию мыши включённой, и на
  телефоне автора она задваивала одиночные тапы: мышиное эхо приходило
  РАНЬШЕ самого касания, подавление по счётчику (`_is_touch_echo`)
  видело эхо ещё до того, как касание взвело счётчик, — буква
  принималась, а её дубль ложился опечаткой на следующую клетку: «Вии»
  вместо «Вид», красная поверх «д», заяц на месте (17.10.2026; на
  десктопе не бывает — там эха нет). При двух пальцах (шифт+буква) эхо
  бывает только у первого пальца, поэтому заглавные не сбоили —
  проблема проявлялась ровно со следующего одиночного тапа. Два слоя:
  **(1)** `emulate_mouse_from_touch=false` в project.godot — телефон
  шлёт только `ScreenTouch`/`ScreenDrag`, эха нет вовсе; скролл списка
  меню и флинг переведены на свою ветку `ScreenDrag` (раньше вело
  мышиное эхо, в main мышиных движений от касаний нет). **(2)** Дедуп в
  `_own_press` — одна клавиша дважды за `TOUCH_ECHO_T` (40 мс) от
  РАЗНЫХ источников вводится один раз: защита от железок, где эхо всё
  же прилетит; окно узкое нарочно — две ПОСЛЕДОВАТЕЛЬНЫЕ буквы «сс»
  это два жеста (между ними ≥60 мс), эхо же приходит в пару кадров.
  Запись дедупа чистится на отпускании (жест кончился — новое нажатие
  вправе напечатать ту же букву хоть сразу). Держит
  `_case_touch_echo_first` (настройка + оба порядка событий; на
  отключённом дедупе краснеет на «метке опечатки» и «курсоре»), плюс
  старые `_case_touch_multitouch` и «быстрая двойная буква» в combo.
- **Долгое нажатие рядом с серыми клетками.** Нажатие вводит букву, а
  заяц уходит дальше (серые проходятся сами). Откат «на одну клетку»
  приземлялся не туда, и «ё» уходило в чужую клетку: метка позади
  зайца. `_long_swap()` возвращает палец на ИХ клетку. Счётчики при
  этом НЕ трогаются: игра считает нажатия, а не буквы на экране
  (стирание бесплатно — это закреплено `logic_test`). Держит
  `_case_long_press_grey`.

## 4. Визуальный тест-цикл (виртуальный экран :99, :0 не трогаем!)

```bash
Xvfb :99 -screen 0 1280x800x24 &   # один раз; живёт сам по себе
setxkbmap -display :99 -model pc105 -layout ru  # ввод кириллицы (потом вернуть us)
DISPLAY=:99 ./game/dist/ModernBabyType.x86_64 &
DISPLAY=:99 .venv/bin/python tools/x11test.py shot <имя>  # скрин в /tmp/opencode/<имя>.png
DISPLAY=:99 .venv/bin/python tools/x11test.py geom   # размер окна
DISPLAY=:99 .venv/bin/python tools/x11test.py focus  # фокус окну игры
DISPLAY=:99 .venv/bin/python tools/x11test.py kc 69  # F3: debug-HUD
setxkbmap -display :99 us  # вернуть раскладку после тестов
```
Пример ввода буквы: `x11test.py key 0x6c1` (через keysym→keycode текущей
раскладки; при `ru` в трее keycode 41 даёт «а» и работает как ввод).

Внимание: `key <keysym>` вводит через физический keycode раскладки (трей `ru`),
для функциональных клавиш использовать `kc <сырой keycode X11>` (F3=69).
Игру на `:99` после проверки гасить сразу (см. раздел 5). На `:0` — наоборот:
после каждого изменения пересобрать, быстро проверить и оставить ЗАПУЩЕННОЙ
окном, чтобы автор мог погонять (`:0` — его экран, `:99` — тестовый).

## 5. Гигиена процессов (стенд :99, контейнеры, эмулятор)

- Эмулятор (`mbt-emu`, qemu) жрёт гигабайты RAM и CPU, пока висит.
  Железное правило (два провала 08.10.2026 — висел 29 минут, потом ещё
  ~20 минут во время правки кнопок; автор заметил оба раза):
  закончил проверку — `docker stop mbt-emu` СРАЗУ, затем контрольный
  `docker ps` и `ps` по qemu. Между проверками (правка кода, сборка,
  тесты) — `docker pause mbt-emu` СРАЗУ, как только эмулятор стал не
  нужен: CPU=0, память остаётся, состояние гостя сохраняется,
  `docker unpause` поднимает мгновенно. Пауза — не «забыл погасить»,
  а нормальный режим ожидания; автор этим и пользуется.
  После КАЖДОГО использования эмулятора в ответе следующим сообщением —
  строка о его состоянии (погашен / на паузе / работает).

- Игра на `:99` без vsync крутит цикл вхолостую и жрёт ~1000% CPU
  (llvmpipe + uncapped FPS; на реальном экране такого нет — там душит
  vsync). Поэтому: запустил для скрина — сразу погасил и проверил `ps`.
  Висящая игра на 20 минут = перегрев машины автора, так уже было
  05.10.2026 (один экземпляр 1107% CPU, плюс два 15-часовых зависших
  теста из оборванных вызовов).
- Запуск и гашение — РАЗНЫМИ командами: строка, где в одном шелле и
  путь к бинарю, и kill по нему, убивает собственный шелл (паттерн
  `[M]` спасает только grep, а не родителя). Шаблон гашения — циклом
  с защитой `ME=$$`, затем контрольный `ps`.
- После любого оборванного вызова (таймаут/abort) — контроль:
  `docker ps` (висящие контейнеры `mbt-godot` — `docker rm -f`) и `ps`
  по игре. Tool-таймаут детей не убивает: `--rm` срабатывает только
  при штатном выходе, зависший godot внутри жил 15 часов.
- `--fixed-fps` цикл НЕ душит (фиксирует только дельту) — для :99 не
  использовать как cap.

## 6. Стенд Android-эмулятора (автор смотрит локальный APK до пуша)

- Запуск: `tools/emulator/run-emu.sh` — окно эмулятора на `:0` (только по
  просьбе автора), свежий `game/dist/ModernBabyType.apk` ставится сам.
  Без окна (себе для скриншотов): `run-emu.sh --headless`, кадры через
  `adb exec-out screencap -p`.
- SDK и образы лежат в `tools/emulator/sdk` (в `.gitignore`, пересоздаются
  sdkmanager'ом; AVD зовётся `mbt`, Play Store-образ — там Gboard с русским).
  KVM пробрасывается устройством + `--group-add` (пользователя в группе `kvm`
  нет — так задумано, наружу ничего не ставится).
- Русская раскладка и экранная клавиатура: в образах кириллицы НЕТ вообще
  (русских KCM в системе нет — ни в AOSP, ни в Play; `-change_locale`
  не помогает). Проверено до конца 05.10.2026 на Play-образе: Gboard
  из коробки, его multilingual-списки русский содержат, НО железные
  клавиши они не перекартируют — в игру приходит латиница (видно по
  красной `f` вместо `б`), у обоих устройств `KeyboardLayoutInfo: <not set>`.
  Без русского KCM в образе русский ввод с физической клавиатуры
  невозможен в принципе. Вызов экранной клавиатуры из игры на стенде
  тоже невозможен — гейт движка: Godot 4.3 (`GodotEditText.showKeyboard`)
  молча запрещает `showSoftInput`, когда в конфигурации гостя числится
  железная клавиатура, а эмулятор всегда ею притворяется. На реальном
  телефоне обоих ограничений нет.
  Следствия для стенда: физическая клавиатура шлёт только латиницу
  (проверено xdotool с хостовой ru-раскладкой — гость всё равно отдаёт
  латиницу: решает карта гостя). Русский ввод на стенде — через
  RU-клавиатуру в игре (см. ниже), путь commitText для кириллицы тот же,
  что для латиницы (unicode), латиница проверена.
  Попытки починить гостя (итог 06.10.2026, всё откачено): своя русская
  KCM (текстовый формат, `\u`-эскейпы — кириллицу литералами и прямые
  `\u` парсер гостя отвергает) кладётся в `/system/usr/keychars`
  (userdebug: root + remount + push, переживает ребут), устройство
  `qwerty2` её резолвит, ошибок парсинга нет — но маппинг НЕ применяется
  (доказано подменой A→X в ASCII: всё равно `a`). Гостевые KCM
  игнорируются полностью. Флаг `-charmap` (свой goldfish-формат
  `KEYCODE display number base caps fn caps_fn`, кириллица hex'ами —
  парсер эмулятора его ест) для эффекта требует окна и живых X-клавиш,
  headless+sendevent его не проверяют. Файл хост-карты:
  `tools/emulator/keys/ru-host-charmap.txt`, гостевая:
  `tools/emulator/keys/qwerty2.kcm` (обе лежат запасными).
  Вызов экранной клавиатуры из игры на стенде невозможен — гейт движка:
  Godot 4.3 (`GodotEditText.showKeyboard`) молча запрещает `showSoftInput`,
  когда в конфигурации гостя числится железная клавиатура, а эмулятор
  всегда ею притворяется. Проверено вплоть до `hw.keyboard=no` на копии
  AVD (копия снесена): конфиг всё равно `qwerty` (virtio-тачи рекламируют
  KEYBOARD-источник). На реальном телефоне обоих ограничений нет.
  Для отладки перекрытий — симуляция клавиатуры F4 (только дебажная
  сборка, `_kb_fake`, высота 42% экрана штатным путём kb_h→_relayout→_eff_h;
  в релизе ветка мертва). Дебажная сборка: `--export-debug AndroidEmu`
  (без `./build-game.sh`, у него только релиз; вызов БЕЗ ведущего `godot`
  — entrypoint образа уже им является, дубль ломает путь вывода).
  В `tools/emulator/keys/` лежат heliboard.apk и simple-keyboard.apk
  (запасные; у Simple Keyboard русского нет).
  `adb shell input tap` в госте НЕ работает (даже по системным кнопкам),
  зато настоящие клики мышью в окне доходят как тачи (проверено через
  `getevent`: есть ABS_X/ABS_Y + down/up) — ими же жать Allow в диалоге
  USB-отладки (xdotool'ом, не руками). `input keyevent` и DPAD — да;
  по спискам настроек ходить TAB'ом, тумблер дёргать DPAD_CENTER, фокус
  проверять через `uiautomator dump` (пулить XML и грепать на хосте —
  греп в контейнере на большом XML сегфолтится, python3 в образе нет).
